# Research Log — 2026-09-25

## Objective

Begin genuine external-data work rather than adding another synthetic stress test. The goal was to retrieve a public real-world dataset that covers a Device Trust dimension LANL does not expose, implement a reproducible component adapter, evaluate it without label leakage, and record strict claim boundaries.

## Fresh-source verification

Verified on 2026-09-25:

- Microsoft `cloud-monitoring-dataset`: 67 real-world production telemetry time series across eight domains; includes Windows application crash rate by OS version and country; anomaly points are labeled using domain experts. Repository is public, archived/read-only, and MIT licensed.
- LANL Unified Host & Network 2017: approximately 90 days of de-identified Windows host and network telemetry; daily host files are behind LANL's data-fence form requesting an email and intended research use.
- LANL Comprehensive Multi-Source 2015: 58 days, five data sources, 1,648,275,307 events, and a small known-red-team event file; protected download flow likewise requests an email/use declaration.
- DARPA OpTC: controlled Windows 10 evaluation, approximately 1 TB compressed JSON-compatible telemetry, collected from about 500 hosts, with red-team ground truth; unsuitable for an unbounded full download in this environment.
- Microsoft GUIDE: peer-reviewed publication DOI 10.1145/3701716.3715209; 13M pieces of evidence across 1M real security incidents with analyst triage labels.
- Loghub Windows: CBS servicing logs aggregated from a lab computer running Windows 7, 226+ days; suitable only for narrow servicing/update feature feasibility.

## Implementation

Added:

- `src/microsoft_cloud_health_adapter.py`
- `tests/test_microsoft_cloud_health_adapter.py`

The adapter computes a causal reliability proxy. For each time point it uses only the preceding 48 observations, calculates a rolling median and MAD, converts positive robust deviation into `anomaly_risk`, and maps `endpoint_health = 1 - anomaly_risk`.

Expert anomaly labels are used only during evaluation, not during feature construction.

Targeted local unit tests: **3/3 passed**.

## External component result

Across all 19 production crash-rate series:

- evaluated after warm-up: 15,733 points
- expert-labeled anomalies in evaluated region: 1,192
- macro-average raw-value ROC AUC: 0.8190
- macro-average causal robust-risk ROC AUC: 0.7684
- causal robust-risk AUC range: 0.5609 to 0.9376

Full per-series results are recorded in:

`results/microsoft-cloud-health-pilot.md`

## Interpretation

This is a useful **negative/mixed result**, not a success claim.

A transparent causal robust transform can extract externally grounded reliability signal from some real production series, but performance varies substantially by telemetry context and is weaker on average than raw crash-value ranking.

Therefore the paper should not claim that the current transform is a universal endpoint-health estimator.

The defensible conclusion is narrower:

> Real production reliability telemetry can externally ground the endpoint-health dimension, but the mapping from telemetry to trust must itself be validated per source/context rather than assumed to transfer through one fixed threshold or normalization rule.

## Claim boundary

This experiment does **not** validate:

- full Device Trust effectiveness;
- per-device access decisions;
- Intune compliance;
- Entra identity risk;
- Defender risk;
- patch posture;
- production breach prevention.

The Microsoft data are aggregate crash-rate time series and provide only component-level endpoint-health/reliability evidence.

No unrelated external datasets were concatenated into artificial complete endpoint records.

## Research design update

Added `experiments/external-validation-matrix.md` to formally separate four evidence levels:

1. synthetic mechanism/stress evidence;
2. unlabeled real-enterprise feature plausibility;
3. independently labeled component validation;
4. jointly observed multidimensional endpoint state plus access outcomes.

The current public-data program reaches levels 2–3 only.

## Limitations

- Microsoft crash telemetry is aggregate rather than endpoint-level.
- The 48-point window and risk scaling are untuned transparent research choices.
- ROC AUC measures ranking, not a deployable access-control operating point.
- Cross-series heterogeneity is substantial.
- LANL protected files were not downloaded because the provider requires user-supplied email and intended-use information.
- OpTC was not pulled wholesale because the public corpus is approximately terabyte scale; a bounded slice must be specified.
