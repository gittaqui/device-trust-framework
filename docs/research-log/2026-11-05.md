## Predeclared estimands and paired analysis
For device i, interval t, policy a, and persistence condition r, define U_i as its frozen scenario-level unsafe indicator, A_itra=1 if decision is ordinary ALLOW, D_itra=1 if DENY, and S_itra=1 if STEP_UP. Define T as the common number of observed intervals.

- Unsafe ALLOW rate R_U(r,a) = sum_i U_i sum_t A_itra / [T sum_i U_i]. Report the number of distinct unsafe devices and their total intervals; do not present the denominator as independent samples.
- Safe DENY R_D(r,a) and safe STEP_UP R_S(r,a) use 1-U_i in the numerator and denominator, respectively. Report both separately; do not silently count STEP_UP as DENY.
- Device-average exposure: compute each device's fraction of intervals with ALLOW and average across unsafe devices (or safe devices for friction). For equal T this equals the interval-weighted estimate; with unequal T, report both explicitly.
- For two persistence conditions r1 and r0, paired effect Delta_U(a) = R_U(r1,a)-R_U(r0,a). Use identical frozen device signals and scenario labels, and document whether the random-number streams are genuinely paired across masks. A paired comparison of outcomes is not a causal enterprise estimate.
- For decision instability, define F_i = sum_(t=2)^T 1{decision_it != decision_i,t-1}/(T-1), then average across devices. Keep within-device transitions separate from transitions between devices. Also report flips from ALLOW to DENY/STEP_UP and reverse transitions.
- Report mask missingness, estimated transition probabilities, right-censored run counts, and observed-weight coverage alongside access outcomes; never equate telemetry coverage with access-decision coverage.

## Inference protocol
Primary uncertainty: nonparametric **device-cluster bootstrap**. For each of B=2,000 prespecified replicates (seed 20261105), sample N device IDs with replacement, retaining each selected device's entire longitudinal trajectory **under every compared policy and persistence condition**. Recompute the complete paired effect from resampled device-level numerators and denominators, not from independently resampled time points. Report percentile 2.5/97.5 bounds, distinct-device counts, and Monte Carlo bootstrap seed. If a replicate has no eligible unsafe or safe devices, mark it undefined and disclose the count; do not silently impute zero. Check robustness with B=5,000 and with a device-level paired-difference analysis.

For a common infrastructure outage shared across devices, resampling devices alone is **not** a valid uncertainty estimate for independent outage episodes. Treat independently simulated infrastructure episodes as the outer resampling unit; retain all affected devices and intervals within each episode. If only one common outage realization exists, report descriptive rates and no episode-level confidence interval. The number of independent devices is not a substitute for the number of independent infrastructure episodes.

The bootstrap interval quantifies simulation sampling variation under the stipulated generator and fixed scoring rule. It does not cover generator misspecification, label construction bias, threshold selection, or real-world domain shift. No inferential p-value should be interpreted as deployment evidence.

## Acceptance checks for subsequent implementation
1. Assert unique device IDs and exactly T intervals per device in the balanced arm; check no time transitions cross device boundaries.
2. Assert per-device unsafe/safe labels and underlying posture are constant in the frozen-posture arm.
3. Verify rate numerators never exceed denominators, decision categories partition each evaluated interval, and all paired arms use the same eligible device set.
4. Verify resampling preserves whole trajectories and paired arms; compare against an intentionally invalid row-level bootstrap in a deterministic test to expose underestimated uncertainty under persistent outcomes.
5. Include zero-eligible-class and one-device edge-case tests; do not claim a valid confidence interval with too few independent clusters.
6. Reproduce frozen November 1 observation-level results only where data-generation assumptions are equivalent; otherwise document why they differ.
7. Run targeted tests, repository-wide tests, and full manuscript compilation before adding numerical results to the paper.
