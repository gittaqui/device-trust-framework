# Research Log — 2026-09-07

## External Windows host-event ingestion and anti-leakage protocol

Completed:
- Inspected the full research log before adding new work and followed the prior decision to stop tuning identity guard thresholds on the synthetic generator.
- Re-verified the official LANL 2017 Unified Host and Network Data Set documentation. LANL describes approximately 90 days of de-identified enterprise Windows host/network telemetry and publishes the Windows host-event schema, daily-file organization, public-release information, and dataset citation DOI `10.1142/9781786345646_001`.
- Added `src/lanl_2017_host_adapter.py`, a streaming JSON-lines adapter for the 2017 Windows host events. It derives explicit prior-history proxies for user-host novelty, authentication-failure history, explicit credentials, privileged logons, process novelty, activity freshness, identity assurance, and anomaly risk.
- Designed the adapter to compute history-based features before updating state with the current event, preventing direct current-event leakage into novelty and prior-history features.
- Added `tests/test_lanl_2017_host_adapter.py`. Five tests pass locally, covering the official JSON schema, user-host novelty, prior failure history, process novelty, and bounded streaming summaries.
- Added `experiments/lanl-2017-external-validation-protocol.md` with source provenance, feature mappings, temporal leakage controls, a bounded first-run procedure, checksum requirements, pre-registered descriptive outputs, and explicit limits on claims.
- Added the verified LANL dataset citation to `paper/references.bib`.

Result:
- A tested, auditable ingestion path now exists for independently sourced enterprise Windows telemetry.
- No LANL raw data were downloaded or analyzed in this run, so there are still no real-world performance results. The official LANL download flow requests an email address and description of intended use; that researcher-controlled submission was not automated.

Interpretation:
- The project can now move from synthetic signal distributions to externally observed Windows authentication/process distributions without changing the meaning of public telemetry into product-specific Intune, Entra, or Defender scores.
- Daily LANL files make a bounded first external experiment feasible before attempting the much larger 2015 multi-source corpus.
- The next empirical goal is descriptive calibration and benign-overlap measurement, not immediate threshold optimization.

Limitations:
- The new `identity_assurance` and `anomaly_risk` values remain hand-specified transparent proxies; they are not validated risk probabilities.
- The LANL 2017 dataset does not provide actual Intune compliance, Defender risk, patch posture, or Microsoft Entra risk fields.
- The 2017 release is useful for external behavior distributions but does not, by itself, provide the same red-team ground truth as the earlier multi-source release.
- No real LANL event counts or model-error rates are reported yet.

Next:

2. Run the pre-registered 100,000-event bounded descriptive analysis without changing proxy weights after observing the results.
3. Quantify benign overlap between user-host novelty, prior failures, privilege events, and process novelty.
4. Only after the descriptive holdout is established, test how additive, guarded, and STEP_UP policies behave on externally observed feature distributions.
5. Add independently labeled malicious/red-team telemetry before making external false-allow or detection-effectiveness claims.
