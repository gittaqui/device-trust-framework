# Research log — 2026-09-13

## Objective

Close a manuscript-validity gap by measuring computational scalability of the core explainable trust-decision function with repeated timings and uncertainty estimates.

## Repository state inspected

The `main` branch already contained the multidimensional trust model, synthetic scenario generator, threshold/weight sensitivity work, missing-telemetry analysis, identity non-compensation analysis, statistical comparisons, cost-sensitive abstention, LANL adapters, a frozen external-validation protocol, and an attribute-quorum alternative baseline. The manuscript states RQ3 on computational practicality and mentions scale tests, but no dedicated scalability benchmark artifact was present.

## Fresh source verification

Tomas Kalibera and Richard E. Jones, “Rigorous Benchmarking in Reasonable Time,” ACM SIGPLAN International Symposium on Memory Management (ISMM 2013), pp. 63–74, DOI `10.1145/2464157.2464160`, was rechecked against the University of Kent repository/version-of-record metadata. The paper motivates repeated benchmark execution and explicit treatment of measurement uncertainty.

## Work completed

- Added `src/evaluate_scalability.py`, a dependency-free repeatable microbenchmark for the core `calculate_trust` path.
- Added `tests/test_scalability.py` for decision counting, summary statistics, and repetition validation.
- Added `results/scalability-microbenchmark-results.md` with measured results, environment, interpretation, and limitations.
- Updated the manuscript to report the scalability result narrowly and to separate core-computation throughput from end-to-end enterprise scalability.
- Added the verified benchmarking-methodology reference to the bibliography and literature matrix.

## Validation

The first targeted test run found a defect in the benchmark implementation: Student-t critical values were indexed by repetition count instead of degrees of freedom. The defect was corrected before any results were recorded.

After correction:

- `PYTHONPATH=src pytest -q tests/test_scalability.py`
- result: **3 passed**

The benchmark was then executed using 7 repetitions and 20,000 warm-up decisions for sizes 10,000, 100,000, and 500,000.

## Result

Measured mean throughput ranged from approximately **177,178 to 181,848 core trust decisions per second**, corresponding to **5.50–5.64 microseconds per decision** in this environment. The 500,000-decision run took 2.749543 seconds on average (95% t interval 2.699639–2.799448 seconds). Runtime grew approximately proportionally with decision count across the tested range.

## Interpretation

The core transparent scoring and gating logic is not computationally heavy in this single-process microbenchmark. This supports a limited RQ3 statement that the calculation itself is unlikely to be the dominant performance bottleneck.

It does **not** validate production scalability. Telemetry ingestion, normalization, data joins, network/API latency, policy distribution, enforcement, concurrency, storage, and failure handling are outside the timed region and may dominate a real deployment.

## Evidence classification

This is a **runtime microbenchmark**, not synthetic security-effectiveness evidence and not real-world deployment evidence. No confidential employer data was used.

## Limitations

- Shared/virtualized benchmark host; CPU affinity and frequency controls were not available.
- One Python version and one host environment only.
- Single-process execution only.
- Fixed in-memory inputs; no I/O.
- No production traffic mix or concurrency model.
- Targeted tests passed, but this run does not claim a fresh full-repository test-suite pass.

## Next step

The highest-value empirical step remains the frozen external-validation protocol on official LANL telemetry. For RQ3 specifically, a later systems-level benchmark should add concurrent ingestion/normalization and report end-to-end latency distributions rather than extrapolating from this microbenchmark.
